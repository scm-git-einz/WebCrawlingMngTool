# 크롤링 관리 웹 대시보드 — UI 설계 문서

## 1. 개요

CLI 기반의 크롤링 플랫폼을 **React 기반 웹 UI**로 전환하여, 브라우저에서 사이트 등록/설정/실행/결과 확인/OCR 이력 조회를 모두 관리할 수 있도록 한다.

```
┌──────────────────────────────────────────────────────────────┐
│                    시스템 구성도                                │
│                                                              │
│  ┌──────────────┐   proxy    ┌──────────────┐               │
│  │   React 18   │ ────────→  │   FastAPI     │               │
│  │   Vite       │ :5173      │   uvicorn     │ :8000         │
│  │   SPA        │ ←────────  │   REST API    │               │
│  └──────────────┘   JSON     └──────┬───────┘               │
│                                      │                       │
│                              ┌───────┴───────┐               │
│                              │   SQLite DB    │               │
│                              │  crawling.db   │               │
│                              └───────────────┘               │
└──────────────────────────────────────────────────────────────┘
```

## 2. 기술 스택

| 영역 | 기술 | 버전/포트 | 선정 이유 |
|------|------|----------|----------|
| Frontend | React + Vite | 18, :5173 | 사용자 요청 (React 기반), 빠른 빌드 |
| Backend | FastAPI + uvicorn | :8000 | Python/CrawlDB와 자연스러운 통합, 비동기 지원 |
| 라우팅 | react-router-dom | v6 | SPA 페이지 전환 |
| 차트 | recharts | - | OCR 사용 통계 시각화 |
| 스타일 | CSS Variables + 커스텀 CSS | - | 경량, 외부 의존성 없음 |
| DB | SQLite | - | 기존 `core.db.CrawlDB` 활용 |
| 통신 | Vite proxy → FastAPI | /api/* → :8000 | CORS 우회, 개발 편의 |

**핵심 기능 목록**:

| 기능 | UI 요소 | API |
|------|--------|-----|
| 사이트 목록 조회 | 카테고리별 그룹 테이블 | `GET /api/sites` |
| 카테고리 필터 | 버튼 그룹 (아이콘 + 건수) | 클라이언트 필터링 |
| 활성/비활성 전환 | 토글 스위치 | `PUT /api/sites/{id}/toggle` |
| 수집 주기 설정 | 인라인 드롭다운 (시간/일간/주간/월간) | `PUT /api/sites/{id}/schedule` |
| 설정 편집 | 모달 (에이전트별 다른 폼) | `GET /api/sites/{id}`, `PUT /api/sites/{id}/config` |
| 개별 실행 | 행별 ▶ 버튼 | `POST /api/crawl/run` |
| 카테고리 일괄 실행 | 카테고리 헤더 일괄 실행 버튼 | `POST /api/crawl/run` |
| 전체/주기별 실행 | 상단 실행 바 | `POST /api/crawl/run` |
| 실행 상태 모니터링 | 실행 중 바 (5초 폴링) | `GET /api/crawl/status` |
| 사이트 추가 | AddSiteModal | `POST /api/sites` |

**실행/중지/로그 상태 표시**:
```
사이트 행 버튼:
  미실행 → [▶ 실행] 녹색  [📋 로그]
  실행 중 → [■ 중지] 빨간색  [📋 로그]
  중지 시 → ConfirmModal(danger) 확인 후 즉시 ▶로 전환

실행 중 → 🔄 실행 중 (N)  [사이트A (PID: 1234)] [사이트B (PID: 5678)]
         └── running-status-bar: 파란색 배경, 5초 간격 폴링

실행 완료 → ✅ A매장 크롤링 시작 (PID: 1234)
           └── run-results-bar: 녹색 배경, 5초 후 자동 소멸

로그 뷰어 (LogViewerModal):
  - 다크 터미널 테마 (#1a1a2e 배경, 모노스페이스)
  - 2초 간격 자동 갱신 (tail 방식)
  - 자동 스크롤 + 수동 스크롤 시 일시정지
  - 상태 배지: 실행 중 (pulse 애니메이션) / 완료 / 중지됨
```

### 6.3 설정 모달 (ConfigModal)

에이전트 유형별로 다른 설정 폼을 표시한다.

#### 6.3.1 Product 설정 (ProductConfig)

```
┌── A매장 [product] ──────────── × ─┐
│                                    │
│  수집 모드                          │
│  ┌────────────┐ ┌────────────┐    │
│  │ 🏪 단일 매장 │ │ 🌐 도메인전체│    │
│  │ (selected)  │ │            │    │
│  │ 등록 URL의   │ │ 도메인 내   │    │
│  │ 특정 매장만  │ │ 여러 매장   │    │
│  └────────────┘ └────────────┘    │
│                                    │
│  ┌── 매장 수집 ───────────────────┐ │  ← 도메인 전체 모드에서만 표시
│  │ 도메인에 포함된 매장을 탐색      │ │
│  │ 수집 범위: ○ 전체  ○ 건수 지정  │ │
│  │                   [  50  ] 개  │ │
│  └────────────────────────────────┘ │
│                                    │
│  ┌── 상품 상세 수집 ──────────────┐ │  ← 항상 표시
│  │ 매장의 상품 상세정보를 수집     │ │
│  │ 수집 범위: ○ 전체  ○ 건수 지정  │ │
│  │                   [  20  ] 건  │ │
│  └────────────────────────────────┘ │
│                                    │
│                          [ 저장 ]  │
└────────────────────────────────────┘
```

**수집 모드 동작**:
| 모드 | UI 표시 섹션 | Agent 동작 |
|------|------------|-----------|
| 단일 매장 | 상품 상세 수집만 | `_run_single_mode()` — 등록된 URL 매장만 수집 |
| 도메인 전체 | 매장 수집 + 상품 상세 수집 | `_run_domain_mode()` — 도메인 전체 매장 탐색 후 수집 |

**UI → Agent Config 변환**:
| UI 필드 | 저장 값 | Agent 내부 필드 |
|---------|--------|----------------|
| `crawl_mode='single'` | `single` | 단일 매장 파이프라인 |
| `crawl_mode='domain'` | `domain` | 도메인 전체 파이프라인 |
| `store_limit_type='all'` | `count=0` | `max_stores=0` (전체) |
| `store_limit_type='n'`, `count=50` | `count=50` | `max_stores=50` |
| `product_limit_type='all'` | `count=0` | `max_detail_pages=0` (전체) |
| `product_limit_type='n'`, `count=20` | `count=20` | `max_detail_pages=20` |

```
┌─────────────────────────┐

│                          │

│                          │
│  ┌──────────────────┐    │  ← confirm-detail (선택)
│  │ 현재: 활성 → 비활성│    │
│  └──────────────────┘    │
│                          │
│    [취소]    [비활성화]    │  ← confirm-actions
└─────────────────────────┘
```

**적용 대상**:
| 작업 | 아이콘 | 확인 버튼 | 스타일 |

| 설정 저장 | ℹ️ | 저장 | default |
| 크롤링 실행 | ▶️ | 실행 | run |
| 키워드 추가 | ℹ️ | 추가 | default |
| 키워드 삭제 | ⚠️ | 삭제 | danger |

**상태 관리**:

## 12. 설계 원칙

1. **에이전트 유형별 분리**: ConfigModal에서 agent_type에 따라 다른 설정 폼 렌더링
2. **카테고리 자동 매핑**: 사용자가 에이전트 유형을 알 필요 없음, 카테고리만 선택
3. **모든 변경에 확인**: ConfirmModal로 실수 방지
4. **실시간 모니터링**: 5초 폴링으로 크롤링 실행 상태 추적
5. **UI-Agent 분리**: UI는 사용자 친화적 필드, Agent는 내부 필드 → `_normalize_config()`으로 변환
6. **CSS Variables**: 일관된 디자인 토큰으로 테마 관리
7. **외부 의존성 최소화**: recharts만 사용, CSS 프레임워크 없음
